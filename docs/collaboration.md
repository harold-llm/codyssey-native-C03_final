### 수동 통합을 한 이유와 문제
- F의 학습 화면은 백엔드 없이 동작하는 독립 앱이었고, A의 AI 모듈은 백엔드와 별도 계약(`backend_adapter`)으로 만들어져 있었습니다. 두 산출물을 백엔드 API 계약(`04-API-스펙.md`)에 맞춰 하나의 통합 앱으로 합치는 과정에서, B가 파일을 직접 가져와 수정한 뒤 한 커밋(`0e67598`)으로 반영했습니다.
- 그 결과 코드는 `main`에 들어갔지만 **원 작성자의 커밋이 `main` 이력에 연결되지 않았고**, PR #1은 열린 상태로 남았습니다. Git 이력만 보면 모든 작업이 B 한 명의 것으로 보이는 문제가 생겼습니다.

### 보완 (2026-11-23)
- 두 브랜치를 **내용 변경 없는 병합**(`git merge -s ours`)으로 `main`에 합쳐, 원 커밋(작성자·날짜 그대로)을 `main` 이력에 포함시켰습니다. 코드는 이미 반영돼 있으므로 파일은 바뀌지 않습니다(병합 전후 트리 동일).
  - A: `feature/ai-offline` → PR #1의 원 커밋 `995f72a` 연결
  - F: `feature/bloomy-learning-integration` → 원 커밋 `1f83084` 연결
- 기존 `main` 이력은 수정하지 않았습니다. 이미 배포된 `main`을 다시 쓰면 팀원 로컬 저장소·배포와 어긋나고, 작성자를 바꾸면 없던 기록을 만드는 것이기 때문입니다.
- 확인: `git log --graph --oneline main`

## 4. 회고 — 다음에 바꿀 것
- 팀원 산출물은 GitHub에서 PR로 병합한 뒤, 통합을 위한 수정은 그 위에 별도 커밋으로 쌓는다 (작성자 이력 보존).
- 기능 브랜치를 만들 때 백엔드 API 계약(`04-API-스펙.md`)을 먼저 공유해, 통합 시 재작성 범위를 줄인다.
- PR마다 리뷰어 1인을 지정하고(작업 계획서 §6), 리뷰 코멘트를 남겨 협업 기록을 PR 안에 둔다.
