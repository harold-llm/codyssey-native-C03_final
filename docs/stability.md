## 1. 반복 실행 테스트

같은 프로세스에서 가정을 계속 만들고 데일리 루프(오늘 카드·계획·기록·리포트·메시지·상태 확인)를 반복해, 오류·응답 시간·메모리 변화를 봤습니다.

| 실행 | 규모 | 요청 수 | 소요 | 5xx·예외 |
|---|---|---|---|---|
| ① 규칙 기반 (LLM 키 없음) | 가정 500개 × 하루 루프 10회 | 27,000건 | 36.9초 | **0건** |
| ② LLM 실패 주입 (키는 있으나 연결 거부) | 가정 100개 × 하루 루프 5회 | 2,900건 | 5.6초 | **0건** |

**① 응답 시간 (ms, 서버 처리 시간)**

| 요청 | 횟수 | 평균 | p95 | 최대 |
|---|---|---|---|---|
| 가입 (비밀번호 해시 포함) | 500 | 16.2 | 16.8 | 21.1 |
| 아이 등록 + 4주 계획 생성 | 500 | 13.1 | 16.2 | 50.3 |
| 계획 승인 | 500 | 2.0 | 2.4 | 10.9 |
| 오늘의 카드 | 5,000 | 1.2 | 1.4 | 3.0 |
| 학습 계획 | 5,000 | 0.8 | 1.0 | 1.6 |
| 1분 기록 → 코칭 | 500 | 5.8 | 7.7 | 12.0 |
| 주간 리포트 | 5,000 | 1.2 | 1.5 | 4.1 |
| 메시지 목록 | 5,000 | 0.4 | 0.5 | 0.8 |
| 상태 확인 `/api/health` | 5,000 | 0.0 | 0.0 | 0.1 |

**① 메모리 (파이썬 힙, tracemalloc)** — 가정 50개마다: 2.3 → 2.4 → 2.5 → 2.6 → 2.7 → 2.7 → 2.8 → 2.9 → 3.0 → 3.1 MB.
가정 500개 동안 0.8MB 늘었고 급증은 없었습니다. 증가분은 가정 수에 비례하는 캐시·데이터로 보이며, 서버리스 운영에서는 요청마다 함수가 새로 뜨거나 재사용되므로 장시간 누적되지 않습니다.

**② LLM 실패 주입** — 코칭 단계의 Claude 호출 175회가 모두 실패(연결 거부)했지만, 전부 같은 A·B·C 규칙의 규칙 기반 메시지로 응답했고 5xx는 0건이었습니다. 4주 계획도 LLM이 실패하자 RAG 엔진이 로컬 검색 기반 초안(20일)으로 대체했습니다.

### 이 테스트의 범위
- 서버 로직(`dispatch`)만 측정했습니다. 네트워크 지연, Vercel 콜드 스타트, 실제 Claude 응답 시간(수 초)은 포함되지 않습니다.
- 동시 접속 부하 테스트가 아니라 순차 반복 테스트입니다.
- 운영 환경의 장기 모니터링 기록은 없습니다. 운영 상태는 `/api/health`로 확인합니다.

## 2. 예외 처리 구조

| 실패 지점 | 처리 | 위치 |
|---|---|---|
| Claude 호출 시간 초과·연결 실패 | 시간 제한(15~40초) 후 규칙 기반으로 폴백 | `backend/coach.py`, `Bloomy-AI/ai/llm.py` |
| AI 출력이 JSON 스키마에 안 맞음 | 메모 의도 분류는 **1회 재시도**, 그래도 실패하면 키워드 규칙 | `coach.classify_memo_intent` |
| 계획에 검색 후보 밖 자료가 나옴 | 스키마 `enum`으로 후보 ID만 허용 + 검증에서 거부 → 로컬 검색 초안 | `Bloomy-AI/ai/rag/planner.py`, `validator.py` |
| RAG 엔진 자체 오류 | 오류 원인을 로그와 `/api/health`(`last_plan_error`)에 남기고 규칙 기반 계획 | `backend/ai_bridge.py` |
| 요청 처리 중 예기치 못한 예외 | `dispatch`가 잡아 500 JSON으로 응답하고 로그 기록 (서버는 계속 동작) | `backend/main.py` |
| 잘못된 입력 (미래 날짜, 형식 오류, 남의 아이 조회) | 400·403·404로 거부 | `backend/main.py` (스모크 테스트로 검증) |
| 크론 위조 호출 | 비밀 키(`CRON_SECRET`) 불일치면 거부 | `backend/main.py` |
