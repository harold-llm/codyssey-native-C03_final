# 기존 프로젝트 분석

업로드된 이중 ZIP의 내부 `Bloomy-AI/`에 AI 소스, 가상 카탈로그, 문서, 예제와 테스트가 있었습니다. 외부 ZIP의 가이드와 리포트는 기존 전달본 산출물입니다. 내부 소스는 `/workspace/Bloomy-AI`에 풀었고, 사용자 지정 GitHub 참고본은 읽기용으로만 받아 확인했습니다. 확인한 참고본 커밋은 `2bbaa4665175d32c54634bdcb96ce3c1ce94b33d`입니다.

| 확인 대상 | 기존 상태 | 이번 결정 |
|---|---|---|
| `01-기획서.md` v0.5 §5.2·§6.2 및 `ai/rag/` | 문서는 RAG+LLM을 요구합니다. 핸드오프는 TF-IDF 검색과 정적 템플릿의 계획 초안을 지원합니다. | TF-IDF와 검증을 재사용하고 모델의 순서 구성과 JSON 스키마 검증을 추가합니다. 신경망 임베딩과 별도 전문가 코퍼스는 미구현입니다. |
| v0.5 §5.4·§6.3 및 `ai/agent/` | C → B → A, 휴식일, 가상 승인 및 조정 규칙이 구현돼 있습니다. 핸드오프 분류와 메시지는 로컬 방식입니다. | 별도 분류 호출과 제한된 메시지 구성 호출을 추가합니다. Python 규칙이 분기와 조정을 결정합니다. |
| v0.5 §6.4 및 `ai/memory/` | SQLite 아이별 이력·선호·응답 요약, 중복 처리, 삭제, 저장소 프로토콜이 있습니다. | SQLite를 재사용하고 최근 7일 원본 조회와 원자적 정정을 추가합니다. PostgreSQL 어댑터와 공통 스키마 변경은 제외합니다. |
| `02-요구-명세서.md` 및 v0.5 | 요구 명세서의 일부 표에는 3~6세, 범주형 피드백, 요금 모델, 규칙 계획이 남아 있습니다. | 아이 4~7세, 1~5점, 승인 초안·RAG+LLM에 대해 사용자 요청과 기획서 v0.5, 최신 API 계약을 우선합니다. |
| `03-작업-계획서.md`, `04-API-스펙.md`, `backend/` | 팀 백엔드가 인증·플랜 승인·카드 반영·피드백·DB를 보유합니다. `backend/coach.py`와 `branch.py`에도 독립 분류·코치가 있습니다. | 기존 라우트와 DB 파일을 편집하지 않습니다. 백엔드 연동 시 코치 진입점을 한 곳에서 호출하고 카드 변경과 승인 적용은 백엔드가 소유합니다. |

계획 업로드는 `POST /api/children/{id}/plans`, 승인 처리는 `POST /api/children/{id}/plans/{plan_id}/approve`입니다. AI 응답의 `to_backend_payload()`가 전자에 맞는 필드를 반환합니다. 기존 백엔드 피드백 라우트와 코치 구현은 참고 자료로 확인했습니다. 신규 모듈은 자체 HTTP 라우트를 추가하지 않았습니다.
